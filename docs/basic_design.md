## **2\. 基本設計書の位置付け**

本書は、要件定義書で確定した機能要件（FR）／非機能要件（NFR）を実現するために、画面・データ・処理の外部仕様を具体化することを目的とする。  
本書では「画面の構成」「画面遷移」「入出力項目」「データ構造」「主要処理フロー」までを確定し、詳細設計（内部設計）での実装判断を最小化する。

---

**3\. システム概要**  
**3.1 システム目的**  
オンライン上で雑貨を販売できるECサイトを構築する。初期フェーズでは購買フローの成立を最優先し、将来的な機能追加を阻害しない土台を整える。

**3.2 前提（要件定義より）**

* 商材：雑貨（サイズ／色などのSKU分割は扱わない。1商品＝1在庫単位）  
* 利用端末：PC・スマートフォン・タブレット  
* 購入：ログインユーザーのみ  
* 決済：外部決済連携なし  
* 商品／在庫：初期データ投入済み（seed）。本フェーズでは管理画面なし  
* 技術：Java 17、Servlet／JSP、DB（MySQL）

---

**4\. システム構成（方式設計・概要）**  
**4.1 構成概要**

* Webアプリケーション：Servlet がリクエストを受け付け、処理結果を JSP にフォワードして画面描画する。  
* データアクセス：DAO にて DB にアクセスする。DTO にて画面／処理間のデータ受け渡しを行う。  
* セッション：カート情報をセッションで保持する。  
* DB：商品・在庫・注文・注文明細・ユーザーを管理する。

（注）具体的なディレクトリ構成／クラス設計は詳細設計で定義する。

**4.2 画面表示方針**

* JSPはビュー（画面描画）に限定し、業務判断は Servlet側で行う。  
* 入力値はサーバ側でバリデーションし、エラー時は同一画面にメッセージ表示する。  
* レスポンシブ対応も実施する（最低限の表示崩れがないことは担保）。

**6.3 画面共通仕様**

* 表示通貨：円

* エラーメッセージ表示：画面上部にまとめて表示（項目別エラーも併記可）

**6.4 画面定義（入出力・アクション）**  
6.4.1 G-01 商品一覧画面  
目的：全商品を一覧表示し、カテゴリで絞り込める。  
表示項目：

* 商品一覧  
  * 商品名  
  * 価格  
  * カテゴリ  
  * 商品画像  
  * 詳細への導線（リンク）  
* カテゴリフィルタ（選択）  
* カートへ（リンク）

入力項目：

* カテゴリ（任意）

アクション：

* カテゴリを選択して絞り込み  
* 商品詳細へ遷移  
* カート画面へ遷移

6.4.2 G-02 商品詳細画面  
目的：商品情報を詳細表示し、カートへ追加できる。  
表示項目：

* 商品名、説明、価格、カテゴリ、画像  
* 数量（初期値1）  
* カートに追加（ボタン）  
* 一覧へ戻る（リンク）

入力項目：

* 数量（必須、1以上の整数）

アクション：

* カートに追加（在庫の即時減算は行わない。注文確定時に減算）  
* 一覧へ戻る

6.4.3 G-03 カート画面  
目的：カート内容を表示し、数量変更／削除／注文確定できる。  
表示項目：

* カート一覧  
  * 商品名  
  * 単価（購入時点の価格参照。暫定的に商品価格を表示）  
  * 数量（入力）  
  * 小計（単価×数量）  
  * 削除（ボタン）  
* 合計金額  
 * 数量更新  
* レジへ進む（ボタン）  
* 買い物を続ける（リンク）

入力項目：

* 数量（1以上の整数）

アクション：

* 数量更新（セッション更新）  
* 削除（セッションから除去）  
* レジへ進む（G-04へ遷移）

エラー表示（例）：

6.4.4 G-04 レジ画面

**10\. データ設計**  
**10.1 ER（概念関係）**

* Good（商品） 1 — 1 Stock（在庫）  
* Order（注文） 1 — N OrderItem（注文明細）  
* Good（商品） 1 — N OrderItem（注文明細）

**10.2 テーブル定義（案）**  
（型・制約はMySQL前提。H2でも同等表現が可能な範囲で設計する）

A) goods（商品）

* id：BIGINT PK  
* code：VARCHAR(32) UNIQUE（例：ZAK-001）  
* name：VARCHAR(255) NOT NULL  
* description：TEXT NOT NULL  
* price：INT NOT NULL（円・税込）  
* category：VARCHAR(64) NOT NULL  
* image\_url：VARCHAR(1024) NULL（画像参照URLまたはパス）  
* created\_at：DATETIME NOT NULL  
* updated\_at：DATETIME NOT NULL

B) stocks（在庫）

* good\_id：BIGINT PK、FK \-\> goods.id  
* quantity：INT NOT NULL  
* updated\_at：DATETIME NOT NULL

C) orders（注文）

* id：BIGINT PK  
* user\_id：BIGINT NOT NULL, FK \-\> users.id  
* ordered\_at：DATETIME NOT NULL  
* total\_amount：INT NOT NULL  
* created\_at：DATETIME NOT NULL

D) order\_items（注文明細）

* id：BIGINT PK  
* order\_id：BIGINT NOT NULL、FK \-\> orders.id  
* good\_id：BIGINT NOT NULL、FK \-\> goods.id  
* unit\_price：INT NOT NULL（注文時単価）  
* quantity：INT NOT NULL  
* created\_at：DATETIME NOT NULL

D) users（ユーザー）

* id：BIGINT PK  
* email：VARCHAR(255) NOT NULL  
* password\_hash：VARCHAR(255) NOT NULL  
* last\_name：VARCHAR(32) NOT NULL  
* first\_name：VARCHAR(32) NOT NULL  
* address：VARCHAR(255) NOT NULL  
* card\_number\_last4：VARCHAR(4)（末尾4桁のみ）NULL  
* card\_brand：VARCHAR(32)（VISAなど）NULL  
* card\_exp\_month：TINYINT / card\_exp\_year：SMALLINT NULL  
* card\_name：VARCHAR(255) NULL  
* created\_at：DATETIME NOT NULL  
* updated\_at：DATETIME NOT NULL

インデックス（案）：

* goods(category)  
* order\_items(order\_id)  
* order\_items(good\_id)

**10.3 seedデータ方針**

* goods／stocks は初期投入済みとする。

* 商品一覧／詳細：goods（R）、stocks（R：表示要否は詳細設計で決定）

**12\. 主要処理フロー**  
**12.1 商品一覧表示**

1. categoryパラメータを受け取る（任意）  
2. DAOで商品一覧を取得（必要に応じてカテゴリ条件）  
3. JSPへ一覧を渡して表示

**12.2 カート追加**

1. 商品ID・数量を受け取る  
2. 入力値バリデーション  
3. セッションのカートに商品を追加（既存なら加算または上書き。）  
4. カート画面へ遷移（または詳細へ戻す）

**12.3 注文確定**  
前提：在庫更新と注文保存は同一トランザクションで実行する。

1. セッションからカート内容を取得  
2. DBから対象商品の在庫を取得  
3. 在庫不足があれば処理中断（注文未作成、在庫未更新）  
4. orders を作成  
5. order\_items を作成（単価は注文時点のpriceを保存）  
6. stocks を減算更新  
7. コミット  
8. セッションのカートをクリア  
9. 成功ならG-05 注文完了へ / 失敗ならG-04 レジに戻す

---

**13\. エラー処理・ログ設計（基本方針）**  
**13.1 エラー方針**

* ユーザー入力起因：画面にエラーメッセージ表示（HTTP 200で同画面再表示を基本）  
* 想定外例外：共通エラー画面またはエラー表示  
* 404相当：存在しない商品ID等

**13.2 ログ方針**

* 例外ログ：スタックトレースを含めて出力する  
* SQL／更新追跡：発行SQLまたは更新内容が追えるようにログ設計を行う  
* 注文確定：注文ID、対象商品、数量、在庫更新結果が追跡できるようにする

---

**14\. 外部インターフェース**

* 外部決済サービス連携：なし  
* 外部システム連携：なし  
* 画像：固定URL参照またはローカル参照

**15\. 非機能要件への対応方針**

* 性能：通常利用でストレスのない応答  
* 信頼性：注文確定は整合性維持（途中失敗時ロールバック）  
* 運用：例外ログ、DB操作追跡ログ  
* セキュリティ：入力バリデーション、XSSの基本対策

---

**16\. 受入条件（完了条件）**

* 要件定義書に記載の受入条件に準ずる。  
* 一覧→詳細→カート→注文確定の一連フローが動作すること  
* 注文確定で注文保存・在庫減算が行われること  
* 在庫不足時に注文確定が失敗し在庫が減算されないこと
